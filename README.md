## Features

| Panel | Description |
|-------|-------------|
| **Overview** | Live BTC price sparkline, block stream, chain/node stats grid |
| **Mempool** | Fee-rate histogram, congestion meter, 24-hour mempool history |

| **Lightning** | Channel list with liquidity bars, payment feed, network graph |
| **Search** | Universal explorer — TXIDs, block heights, addresses, LN channels |
| **Alerts** | Rule-based alert engine with severity levels and ACK workflow |

## Quick Start (Demo Mode)

No Bitcoin or Lightning node required.  All data is generated by a realistic
synthetic model (GBM price noise, deterministic block data, randomised mempool).

```bash
# 1. Clone / copy the project
cd bitcoin_terminal

# 2. Create a virtual environment
python3.11 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Run (demo mode is on by default)
python main.py
```

The window opens immediately — no node connection required.

## Connecting to Real Nodes

### Bitcoin Core

1. Add to `bitcoin.conf`:
```ini
server=1
rpcuser=bitcoinrpc
rpcpassword=<strong-random-password>
rpcbind=127.0.0.1
rpcallowip=127.0.0.1
txindex=1          # optional — needed for full TX lookup
```

2. Copy the env template and fill in your credentials:
```bash
cp .env.example .env
# Edit .env with your RPC credentials
```

3. Set `DEMO_MODE=0` and run:
```bash
DEMO_MODE=0 python main.py
```

If the RPC connection fails at startup, the app automatically falls back to
demo mode and logs a warning.

### Lightning Network (LND)

Install `grpcio` and generate protobuf stubs (one-time setup):

```bash
pip install grpcio grpcio-tools

# Download the LND proto files
mkdir -p proto && cd proto
curl -O https://raw.githubusercontent.com/lightningnetwork/lnd/master/lnrpc/rpc.proto

# Generate Python stubs
python -m grpc_tools.protoc \
    -I. \
    --python_out=../bitcoin_terminal \
    --grpc_python_out=../bitcoin_terminal \
    rpc.proto

cd ..
```

Then set your macaroon and TLS cert paths in `.env` and set `DEMO_MODE=0`.

## Architecture

```
bitcoin_terminal/
├── main.py                    Entry point
├── config.py                  All runtime configuration
├── requirements.txt
│
├── backend/
│   ├── rpc_client.py          Bitcoin Core JSON-RPC wrapper + demo generator
│   ├── lightning_client.py    LND gRPC client + demo generator
│   ├── database.py            SQLite persistence (WAL mode, thread-safe)
│   ├── price_feed.py          CoinGecko REST / Binance WS / GBM demo model
│   └── workers.py             QThread workers — Block, Mempool, Whale, LN, Alert
│
└── gui/
    ├── theme.py               QSS stylesheet + colour tokens
    ├── main_window.py         Main QMainWindow — wires all panels + workers
    └── panels/
        ├── overview_panel.py  Price chart, block table, node stats
        ├── mempool_panel.py   Fee histogram, congestion meter, history
        ├── whale_panel.py     Bubble chart, large-TX feed, filtering
        ├── lightning_panel.py Channels, payments, forwarding, graph
        ├── search_panel.py    Universal blockchain explorer
        └── alerts_panel.py    Alert centre with ACK workflow
```

### Data Flow

```
Bitcoin Core RPC ──► BlockWorker ──► OverviewPanel
                 ──► MempoolWorker ──► MempoolPanel ──► DB snapshots
                 ──► WhaleWorker ──► WhalePanel

LND gRPC ──────────► LightningWorker ──► LightningPanel

CoinGecko API ─────► PriceFeed (thread) ──► OverviewPanel ──► DB

DB ────────────────► AlertWorker (every 10s) ──► AlertsPanel
```

All UI updates happen on the Qt main thread via `pyqtSignal`.
Workers run in `QThread` subclasses with clean `stop()` methods called on `closeEvent`.

## Alert Rules

| Trigger | Severity |
|---------|----------|
| Mempool > 100k txs | CRITICAL |
| Mempool > 50k txs | WARNING |
| Max fee rate > 200 sat/vB | CRITICAL |
| Transfer ≥ 1000 BTC detected | WARNING |
| BTC price ±3% in one poll window | WARNING |
| Lightning balance ratio < 10% or > 90% | WARNING |

Alerts are persisted in SQLite and survive restarts.
Same alert type is suppressed for 5 minutes to avoid spam.

## Extending the App

### Adding a new panel
1. Create `gui/panels/my_panel.py` subclassing `QWidget`.
2. Add it to `MainWindow._tabs` in `gui/main_window.py`.
3. Wire any new worker signals in `_connect_signals()`.

### Adding a new alert rule
Open `backend/workers.py` → `AlertWorker._tick()` and append a rule following
the existing pattern.

### Switching to PostgreSQL
Replace `backend/database.py` with a `psycopg2` or `asyncpg` implementation
using the same method signatures.  No other file needs to change.
